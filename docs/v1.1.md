# 📘 Dokumentasi Firmware ESP32 (v1.1)

**Proyek:** SPF Gateway (Growatt SPF Inverter Monitoring)
**Komponen:** ESP32 + MAX485 (RS485 to TTL) + MicroPython
**Fokus Rilis v1.1:** Peningkatan Keandalan (*Reliability*) & Keamanan Penulisan Register (*Write Safety*).

## 🆕 Apa yang Baru di v1.1?
Versi ini dirancang agar ESP32 dapat berjalan tanpa pengawasan (24/7) di lingkungan jaringan yang tidak stabil.
1. **Watchdog Timer (WDT):** Mencegah ESP32 macet total (*hang*) dengan me-restart perangkat secara otomatis jika tidak ada aktivitas selama 60 detik.
2. **Auto-Reconnect WiFi:** Memantau koneksi WiFi setiap putaran. Jika terputus, ESP32 akan otomatis menyambung ulang tanpa harus di-reset manual.
3. **Offline Buffer (RAM):** Jika laptop/server mati, ESP32 tidak akan *freeze*. Data akan disimpan sementara di RAM (maksimal 10 data) dan dikirim saat server kembali online.
4. **Modbus Write Delay & Retry:** Memberikan jeda 1 detik setelah menulis ke EEPROM inverter, dan membaca ulang hingga 3 kali untuk memastikan perintah benar-benar diterapkan.
5. **Garbage Collector:** Membersihkan memori secara berkala untuk mencegah kebocoran memori (Memory Leak).

## 🔄 Cara Kerja (Flow Fitur)

### 1. Alur Utama (Main Loop)
Ini adalah siklus yang berjalan terus-menerus setiap 3 detik (atau sesuai `POLL_MS`).

```text
[Mulai Loop]
   │
   ├──> 1. Feed WDT (Watchdog Timer)
   ├──> 2. Bersihkan RAM (gc.collect)
   │
   ├──> 3. Cek Koneksi WiFi
   │      ├── Jika putus: Coba sambung ulang (Auto-Reconnect)
   │      └── Jika gagal: Tunggu 5 detik, lanjut ke siklus berikutnya
   │
   ├──> 4. Baca Data Inverter (Input Register 0-89)
   │
   ├──> 5. Baca Data Setting (Holding Register) tiap 5 putaran
   │
   ├──> 6. Kirim Data (HTTP POST) ke Server
   │      │
   │      ├── [SUKSES] ──> Kirim data cadangan di Offline Buffer (jika ada)
   │      │                ──> Terima perintah dari server (jika ada)
   │      │                ──> Eksekusi perintah (lihat Alur 2)
   │      │
   │      └── [GAGAL/TIMEOUT] ──> Simpan data saat ini ke Offline Buffer (Max 10)
   │
   └──> 7. Tunggu jeda (3 detik), lalu ulangi dari awal.
```

### 2. Alur Eksekusi Perintah (Write & Retry)
Ini adalah alur ketika Anda menekan tombol "Terapkan" di dashboard untuk mengubah settingan inverter.

```text
[Terima Perintah dari Server]
   │
   ├──> 1. Validasi Register & Range Nilai (Whitelist)
   │
   ├──> 2. Kirim Perintah Modbus Write (Function 06)
   │
   ├──> 3. TUNGGU 1 DETIK (1000ms)
   │      (Memberi waktu inverter menulis ke chip EEPROM-nya)
   │
   ├──> 4. Baca Ulang Register (Read-back)
   │
   ├──> 5. Apakah Nilai Sama?
   │      ├── [YA] ──> Sukses! Laporkan ke server.
   │      └── [TIDAK] ──> Coba lagi baca ulang (Max 3x, jeda 500ms)
   │                     └── Jika tetap gagal: Laporkan Error ke server.
   │
   └──> Lanjutkan siklus utama.
```

### 3. Alur Offline Buffer
Mencegah hilangnya data saat laptop/server dimatikan atau WiFi router bermasalah.

```text
Mengirim data ke server...
   │
   ├── [Sukses] ──> Cek `offline_buffer`. Jika ada isinya, kirim satu per satu.
   │               Jika kosong, lanjut normal.
   │
   └── [Gagal] ──> Cek jumlah `offline_buffer`.
                   ├── Jika < 10 ──> Simpan data payload saat ini ke antrean.
                   └── Jika >= 10 ──> Buang data terlama, simpan data terbaru.
```

## ⚙️ Pengaturan Penting di Kode

Jika Anda ingin mengubah sensitivitas sistem v1.1, Anda bisa mengubah variabel berikut di bagian atas file `main.py`:

| Variabel | Default | Penjelasan |
| :--- | :--- | :--- |
| `POLL_MS` | `3000` | Jeda antar pengiriman data ke server (3 detik). |
| `HTTP_TIMEOUT` | `5` | Waktu tunggu maksimal (detik) sebelum ESP32 menyerah mengirim data ke server. |
| `wdt = machine.WDT(...)` | `60000` | Batas waktu (ms) sebelum ESP32 restart sendiri jika hang (60 detik). |
| `time.sleep_ms(1000)` | `1000` | Jeda di `run_cmd` setelah menulis ke EEPROM. **Jangan diubah sembarangan.** |
| `range(3)` | `3` | Jumlah percobaan baca ulang (read-back) jika nilai tidak cocok. |

## 🛠️ Troubleshooting v1.1

| Gejala di Log | Kemungkinan Penyebab | Solusi |
| :--- | :--- | :--- |
| `Gagal kirim ke server: timeout` | Server mati atau IP salah. | Cek laptop server, pastikan IP di `SERVER_URL` benar. ESP32 otomatis akan menyimpan data ke RAM. |
| `Readback mismatch (Coba 1/3)` | Inverter butuh waktu lebih dari 1 detik untuk menyimpan settingan, atau nilai ditolak firmware. | Jika selalu gagal, pastikan settingan diizinkan saat status inverter (misal: Standby). |
| `WiFi terputus! Mencoba...` | Sinyal router lemah atau router restart. | ESP32 akan terus mencoba menyambung. Jika lebih dari 60 detik, WDT akan me-restart ESP32. |
| `Fatal error: WDT` | Kode macet (biasanya karena library HTTP hang parah). | Biarkan saja, ESP32 akan restart dalam 1 menit dan kembali normal. |
