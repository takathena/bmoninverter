# 📚 Dokumentasi Sistem SPF Gateway (v1.2)

**Deskripsi:** Sistem monitoring dan kontrol jarak jauh untuk inverter Growatt SPF (Off-Grid) menggunakan ESP32 dan server Python lokal.
**Fokus Rilis v1.2:** Keandalan data (*Reliability*) dan Keamanan akses (*Security*).

---

## 1. Arsitektur Sistem (High-Level)

Sistem ini menggunakan arsitektur **Client-Polling**, di mana ESP32 adalah pihak yang selalu aktif memanggil server (bukan server yang memanggil ESP32). Ini memungkinkan server berjalan di laptop biasa tanpa perlu IP publik.

```text
       [ Inverter Growatt SPF ]
                 │
                 │ (Kabel RS485: A & B)
                 ▼
          [ Modul MAX485 ]
                 │
                 │ (TX, RX, DE/RE)
                 ▼
       [ ESP32 (MicroPython) ]
                 │
                 │ 1. HTTP POST (Kirim Data + API Key)
                 │ 2. HTTP Response (Terima Perintah/Command)
                 ▼
       [ WiFi Router / LAN ]
                 │
                 ▼
+---------------------------------------------------+
|               [ Laptop / Server ]                 |
|                                                   |
|  +---------------------------------------------+  |
|  |           FastAPI Server (Python)           |  |
|  |                                             |  |
|  |  - Menerima data (Validasi API Key)         |  |
|  |  - Menyimpan ke SQLite Database             |  |
|  |  - Menyimpan antrean perintah (Commands)    |  |
|  |  - Melayani request Dashboard (Basic Auth)  |  |
|  +---------------------------------------------+  |
|          ▲                          ▲             |
|          │                          │             |
|   (HTTP POST/GET)            (HTTP GET polling)   |
|          │                          │             |
+----------│--------------------------│-------------+
           │                          │
           │                          ▼
           │                  [ Browser (Dashboard) ]
           │                  - Login (Basic Auth)
           │                  - Lihat grafik
           └────────────────  - Ubah settingan
```

## 2. Alur Kerja (Flow) Sistem

### A. Alur Pembacaan Data (Read Flow)
Ini adalah siklus yang terjadi secara otomatis setiap 3 detik. ESP32 membaca data dari inverter dan mengirimkannya ke server.

```text
[ESP32 Mulai] 
      │
      ▼
[1] Baca Input Register (Modbus RTU)
    Alamat 0 s/d 89 (Data Live: PV, Baterai, Beban, Suhu, dll)
      │
      ▼
[2] Baca Holding Register (Tiap 5 putaran)
    Alamat 0 s/d 44 (Data Settingan: Prioritas, Jam, Voltase)
      │
      ▼
[3] Susun JSON Payload
    { "live": {...}, "holding": {...}, "results": [...] }
      │
      ▼
[4] HTTP POST ke Server (/api/ingest)
    Header: X-API-Key
      │
      ▼
[Server Terima] ──> Validasi API Key ──> Simpan ke SQLite ──> Update State RAM
      │
      ▼
[Dashboard] ──> Browser polling GET /api/latest (tiap 3 dtk) ──> Tampilkan UI
```

### B. Alur Perintah Kontrol (Write/Command Flow)
Ini adalah alur ketika Anda mengubah settingan (misal: mengganti sumber *charge* dari PV ke PV+PLN) melalui dashboard.

```text
[User di Dashboard] ──> Klik "Terapkan" 
      │
      ▼
[Server] ──> Validasi Input (Min/Max, Tipe Data, Konflik) 
      │
      ▼
[Server] ──> Simpan ke Antrean `commands` (Status: "menunggu")
      │
      ▼
[ESP32] ──> POST /api/ingest (Siklus 3 detik berikutnya)
      │
      ▼
[Server] ──> Kirim balasan JSON: `{"commands": [{"id": 1, "reg": 2, "value": 1}]}`
      │
      ▼
[ESP32] ──> Terima Perintah
      │
      ├─> 1. Tulis ke Modbus (Function 06)
      ├─> 2. JEDA 1000ms (Beri waktu EEPROM inverter)
      ├─> 3. Baca Ulang (Read-back) maks 3x (jeda 500ms)
      │
      ▼
[ESP32] ──> Simpan Hasil (ok/gagal) ke `results`
      │
      ▼
[ESP32] ──> POST berikutnya ──> [Server] ──> Update Log Audit di Database
```

## 3. Fitur Keandalan (Reliability v1.1)
Sistem ini dirancang agar tidak mudah *crash* meskipun jaringan atau server bermasalah.

1. **Watchdog Timer (WDT)**: Jika ESP32 macet (misal library HTTP *hang*), WDT akan memaksa ESP32 untuk *restart* secara otomatis dalam 60 detik.
2. **Auto-Reconnect**: Jika WiFi terputus, ESP32 akan terus mencoba menyambung kembali tanpa menghentikan program.
3. **Offline Buffer**: Jika laptop/server mati (HTTP Timeout), ESP32 tidak akan *freeze*. ESP32 akan menyimpan data ke dalam RAM (maksimal 10 data). Saat server menyala kembali, ESP32 akan mengirimkan data yang tertunda tersebut.
4. **Modbus Write Retry**: Mencegah kegagalan perintah kontrol. Setelah menulis ke inverter, ESP32 memberi jeda 1 detik, lalu membaca ulang 3x untuk memastikan perintah benar-benar diterapkan.
5. **Garbage Collector**: Membersihkan RAM ESP32 setiap putaran untuk mencegah *memory leak*.

## 4. Fitur Keamanan (Security v1.2)

1. **Basic Authentication**: Dashboard dilindungi username & password. Jika tidak login, browser akan memunculkan popup (Username: `admin`, Password: `growatt123`).
2. **API Key Header**: Server hanya menerima data dari ESP32 jika HTTP Request menyertakan header `X-API-Key` yang nilainya cocok.
3. **Cross-Site Scripting (XSS) Prevention**: Data dari server di-render ke HTML menggunakan `.textContent` (bukan `.innerHTML`), sehingga aman dari injeksi kode jahat.
4. **Validasi Ketat**: Server memblokir penulisan ke register yang tidak diizinkan (*whitelist*) dan memvalidasi batas minimum/maksimum (misal: Voltase Bulk tidak boleh lebih kecil dari Float).

## 5. Kamus Data (Register Mapping)

Sistem ini membagi register menjadi dua kategori:

### A. Input Register (Read-Only / Hanya Baca)
Mengambil data *live* dari inverter.
*   **0**: Status Sistem (0=Standby, 3=Fault, 5=PV Charge, dll)
*   **1-8**: Data PV (Volt, Ampere, Watt)
*   **9-16**: Data Beban / Output AC
*   **17-18**: Data Baterai (Voltase & SOC)
*   **20-21**: Data PLN (Voltase & Frekuensi)
*   **25-27**: Suhu (Inverter, DC-DC, Load %)
*   **77-78**: Daya Baterai (+ Discharge, - Charge)

### B. Holding Register (Read / Write / Bisa Diubah)
Digunakan untuk mengubah settingan inverter.
*   **1**: Prioritas Sumber Output (0=Baterai, 1=PV, 2=PLN)
*   **2**: Prioritas Sumber Charge (0=PV, 1=PV+PLN, 2=PV Saja)
*   **3-6**: Jadwal Penggunaan PLN (Jam Mulai/Selesai)
*   **22**: Buzzer (0=Mati, 1=Nyala)
*   **34-37**: Pengaturan Baterai (Arus Maks, Tegangan Bulk/Float, Tegangan Low)

## 6. Struktur Database SQLite (`spf.db`)

Server menyimpan data dalam dua tabel utama:

1. **`readings`**: Menyimpan histori data *live*.
   *   `ts` (Waktu), `pv_w` (Daya PV), `load_w` (Beban), `bat_v` (Volt Baterai), `soc` (Persentase), `bat_w` (Daya Baterai), `grid_v` (Volt PLN), `inv_temp` (Suhu).
2. **`audit`**: Menyimpan log perubahan settingan.
   *   `ts` (Waktu), `reg` (Alamat Register), `label` (Nama Setingan), `old` (Nilai Lama), `new` (Nilai Baru), `status` (ok/gagal), `detail` (Keterangan Error).

## 7. Troubleshooting (Pemecahan Masalah)

| Gejala | Kemungkinan Penyebab | Solusi |
| :--- | :--- | :--- |
| Dashboard minta password terus | Password salah atau sesi browser habis. | Masukkan `admin` / `growatt123`. Refresh halaman. |
| ESP32 log: `Gagal kirim ke server: 401` | API Key di ESP32 tidak sama dengan di Server. | Buka `main.py` dan `server.py`, pastikan string `API_KEY` sama persis. |
| Setingan gagal diterapkan (Log: `gagal`) | Inverter menolak perintah, atau EEPROM sibuk. | Coba terapkan sekali lagi. Pastikan inverter tidak sedang dalam mode Fault. |
| Grafik tidak muncul | Browser gagal memuat Chart.js dari internet. | Pastikan laptop terhubung ke internet, atau unduh Chart.js secara lokal. |
| Data ESP32 selalu offline | WiFi terputus atau IP Server berubah. | Cek log ESP32 via Serial Monitor. Pastikan IP Laptop di `SERVER_URL` benar. |
