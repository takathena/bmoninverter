# 📚 Dokumentasi Lengkap: SPF Gateway v1.4

**Deskripsi Proyek:** Sistem monitoring dan kontrol jarak jauh (IoT) untuk inverter *off-grid* Growatt SPF (5000 ES / 6000 ES Plus) menggunakan mikrokontroler ESP32 dan server lokal berbasis Python yang berjalan di dalam Docker.

**Status Rilis:** v1.4 (Fokus: Skalabilitas Multi-Inverter & *Deployment* Docker).

---

## 1. Arsitektur Sistem (High-Level)

Di versi ini, arsitektur berubah dari "Single-Device" menjadi **"Multi-Device"**. Satu Server Python dapat melayani banyak ESP32 secara bersamaan. 

```text
  [ Inverter 1 ] ──RS485──> [ ESP32 A ] (device_id: "esp32_rumah")
                                     │
                                     │ HTTP POST (Kirim Data + API Key)
                                     ▼
  [ Inverter 2 ] ──RS485──> [ ESP32 B ] (device_id: "esp32_gudang")
                                     │
                                     │ HTTP POST (Kirim Data + API Key)
                                     ▼
                          [ WiFi Router / LAN ]
                                     │
                                     ▼
+---------------------------------------------------------+
|                  [ Docker Container ]                   |
|                                                         |
|  [ Server Python (FastAPI) ]                            |
|  - Validasi API Key                                     |
|  - Simpan histori berdasarkan `device_id` ke SQLite     |
|  - Proses Otomatisasi SOC & Notifikasi (Telegram)       |
|                                                         |
|  [ SQLite Database (spf.db) ] <── (Volume Mounted ke Host) |
+---------------------------------------------------------+
                                     ▲
                                     │ HTTP GET (polling)
                                     │
                          [ Browser (Dashboard) ]
                          - Login (Basic Auth)
                          - Pilih Inverter via Dropdown
                          - Kontrol & Lihat Grafik
```

## 2. Alur Kerja (Workflows)

### A. Alur Data Multi-Inverter (Read Flow)
Siklus pembacaan data dari masing-masing inverter ke server.

```text
[ESP32 A] ──> Baca Modbus ──> POST /api/ingest (Payload: {device: "esp32_rumah", ...})
                                                   │
                                                   ▼
[Server] ──> Validasi API Key ──> Simpan ke tabel `readings` dengan kolom `device_id`="esp32_rumah"

[ESP32 B] ──> Baca Modbus ──> POST /api/ingest (Payload: {device: "esp32_gudang", ...})
                                                   │
                                                   ▼
[Server] ──> Validasi API Key ──> Simpan ke tabel `readings` dengan kolom `device_id`="esp32_gudang"
```

### B. Alur Dashboard (UI Flow)
Saat pengguna membuka dashboard.

```text
[User Login] ──> [Dashboard] ──> GET /api/devices 
                                      │
                                      ▼
                          Mendapatkan daftar: ["esp32_rumah", "esp32_gudang"]
                                      │
                                      ▼
                          Dropdown terisi. User memilih "esp32_rumah".
                                      │
                                      ▼
                          Dashboard hanya menampilkan data & grafik 
                          yang memiliki `device_id` = "esp32_rumah".
```

### C. Alur Perintah Kontrol (Write Flow)
Saat user mengubah settingan di dashboard.

```text
[User] ──> Klik "Terapkan" (di panel esp32_rumah)
                 │
                 ▼
[Server] ──> Simpan antrean: {device_id: "esp32_rumah", reg: 2, value: 1}
                 │
                 ▼
[ESP32 A] ──> POST /api/ingest (Siklus berikutnya)
                 │
                 ▼
[Server] ──> Cek antrean: Apakah ada perintah untuk "esp32_rumah"? (Ya)
                 │
                 ▼
[Server] ──> Kirim JSON: {"commands": [{"id": 1, "reg": 2, "value": 1}]}
                 │
                 ▼
[ESP32 B] ──> POST /api/ingest (Mengirim data gudang)
                 │
                 ▼
[Server] ──> Cek antrean: Apakah ada perintah untuk "esp32_gudang"? (Kosong)
                 │
                 ▼
[Server] ──> Kirim JSON: {"commands": []}  <── ESP32 B tidak terganggu
```

## 3. Panduan Deployment Docker

Docker memastikan server Python berjalan di lingkungan yang terisolasi dan dapat menyala otomatis jika laptop/server restart.

### Struktur Folder
Pastikan folder proyek Anda terlihat seperti ini:
```text
spf-gateway/
├── data/                  <── (Dibuat otomatis oleh Docker)
│   └── spf.db             <── Database SQLite
├── Dockerfile
├── docker-compose.yml
├── server.py
├── dashboard.html
├── requirements.txt
└── .dockerignore
```

### Konfigurasi File

**1. `Dockerfile`**
```dockerfile
FROM python:3.11-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
CMD ["python", "server.py"]
```

**2. `docker-compose.yml`**
```yaml
version: '3.8'
services:
  spf-gateway:
    build: .
    container_name: growatt-server
    ports:
      - "8000:8000"
    volumes:
      - ./data:/app/data  # Menyimpan database di luar container
    restart: unless-stopped
```

**3. `.dockerignore`** (Mencegah file sampah masuk ke container)
```text
__pycache__
*.pyc
*.db
data/
.git
```

### Cara Menjalankan
1.  Buka terminal/CMD di folder proyek.
2.  Jalankan perintah:
    ```bash
    docker-compose up -d --build
    ```
3.  Buka browser ke `http://localhost:8000`.
4.  **Mematikan Server:** `docker-compose down`
5.  **Melihat Log Server:** `docker-compose logs -f`

## 4. Peta Register Modbus (Ringkasan)

*Catatan: Konfigurasi lengkap ada di `server.py`.*

| Alamat | Parameter | Skala | Keterangan |
| :--- | :--- | :--- | :--- |
| **Input 0** | Status | - | 0=Standby, 3=Fault, 5=PV Charge, dll |
| **Input 17** | Voltase Baterai | 0.01 | Volt |
| **Input 18** | SOC Baterai | 1 | Persen (%) |
| **Input 77-78** | Daya Baterai | 0.1 | Watt (+ Discharge, - Charge) |
| **Holding 1** | Prioritas Output | - | 0=Baterai, 1=PV, 2=PLN |
| **Holding 2** | Sumber Charge | - | 0=PV, 1=PV+PLN, 2=PV Saja |
| **Holding 3-6** | Jam Operasional PLN | - | Jam (0-23) |
| **Holding 34-37**| Limitasi Baterai | Bervariasi | Arus, Bulk, Float, Low Voltage |

## 5. Roadmap: Menuju Arsitektur Multi-Tenant (SaaS)

Fondasi Multi-Inverter di v1.4 ini adalah langkah awal menuju **Multi-Tenant** (aplikasi berbayar yang bisa digunakan banyak pengguna). Jika Anda ingin melanjutkan proyek ini ke level komersial, berikut adalah yang perlu dirombak:

1.  **Database User:** Buat tabel `users` (id, nama, email, password, role) dan tabel `devices` (id, user_id, nama_device).
2.  **Autentikasi (JWT):** Ganti *HTTP Basic Auth* dengan JWT (JSON Web Token) atau *Session/Cookie* agar bisa membedakan sesi login antar pengguna.
3.  **Pemisahan API Key:** Setiap ESP32 harus memiliki `device_token` unik, bukan API Key global yang sama untuk semua perangkat.
4.  **Isolasi Data:** Saat user login, pastikan query database hanya mengambil data `WHERE user_id = X`. Jangan sampai User A melihat data User B.
5.  **Hosting Cloud:** Pindahkan Docker container dari laptop ke VPS (misal: DigitalOcean, AWS, atau VPS lokal) agar bisa diakses dari mana saja dengan domain dan HTTPS (SSL).

## 6. Troubleshooting

| Gejala | Kemungkinan Penyebab | Solusi |
| :--- | :--- | :--- |
| **Container Docker gagal menyala** | Port 8000 sudah dipakai aplikasi lain. | Matikan aplikasi lain, atau ubah `ports: "8001:8000"` di `docker-compose.yml`. |
| **Data hilang saat container restart** | Volume tidak terpasang dengan benar. | Pastikan folder `data/` ada di folder yang sama dengan `docker-compose.yml`. |
| **Dropdown Inverter kosong** | ESP32 belum mengirim data atau API Key salah. | Cek log ESP32, pastikan `API_KEY` cocok dan server menyala. |
| **Grafik kosong saat ganti device** | Belum ada histori untuk device tersebut. | Tunggu beberapa menit agar ESP32 baru mengirim data, lalu *refresh* halaman. |
| **Lupa Password Dashboard** | Lupa setelan di `server.py`. | Buka `server.py`, ubah `DASHBOARD_PASS`, lalu jalankan `docker-compose up -d --build` ulang. |
