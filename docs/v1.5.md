# 📚 Dokumentasi Lengkap: SPF Gateway v1.5

**Deskripsi Proyek:** Sistem monitoring dan kontrol jarak jauh (IoT) untuk inverter *off-grid* Growatt SPF (5000 ES / 6000 ES Plus) menggunakan ESP32 dan server Python (FastAPI) yang berjalan di Docker.

**Status Rilis:** v1.5 (Fokus: Stabilitas Server, Transparansi Setingan Inverter di Dashboard, dan Kemudahan Debug).

## 2. Perubahan Server (`server.py`)

### A. Perbaikan Deadlock (`Lock` → `RLock`)
**Masalah:** `ingest()` memegang `lock`, lalu memanggil `audit()` yang juga memakai `with lock:`. Dengan `threading.Lock` biasa, thread menunggu dirinya sendiri sehingga **seluruh server hang** dan ESP32 hanya menunggu respons. Terpicu saat Auto-SOC membuat perintah, atau saat hasil perintah masuk.

**Solusi:**
```python
lock = threading.RLock()   # boleh dimasuki ulang oleh thread yang sama
```

### B. Telegram Tidak Lagi Memblokir
Pengiriman Telegram dipindah ke thread terpisah (`daemon=True`). Token salah atau internet lambat tidak menahan request ESP32 (sebelumnya bisa menahan sampai 5 detik di dalam lock). Notifikasi dilewati otomatis jika `TELEGRAM_TOKEN` atau `TELEGRAM_CHAT_ID` kosong, dengan jeda minimal 300 detik antar pesan.

### C. Endpoint Baru
| Endpoint | Auth | Fungsi |
| :--- | :--- | :--- |
| `GET /health` | Tidak ada | Cek server hidup + daftar `device_id` yang pernah mengirim data |

### D. Perbaikan Kecil
- Setiap ingest dicetak ke log: `[ingest] esp32_rumah ok=True err=None results=0`.
- Indeks `idx_readings (device_id, ts)` agar grafik dan ekspor CSV tetap cepat saat data membesar.
- `pv_w` aman terhadap nilai `null` dari ESP32.
- Pembacaan `holding` aman jika device baru belum mengirim holding register.
- Label diganti ke istilah proyek: **Voltase Bulk**, **Voltase Float**, **Ampere Charge Maks**.

### E. Autentikasi Dashboard
Dashboard memakai **halaman login (form) + cookie sesi** (`session_token`, `httponly`), bukan Basic Auth seperti di dokumentasi lama.
- Sesi disimpan di RAM server → **semua sesi hilang saat container restart**, cukup login ulang.
- ESP32 tetap memakai header `X-API-Key`.

## 3. Perubahan ESP32 (`main.py`)

### A. `post()` Mengecek Status HTTP
**Masalah:** respons `401` dianggap sukses karena hanya `r.json()` yang dipanggil, sehingga ESP32 terlihat "jalan" tanpa error.

**Solusi:**
```python
def post(payload):
    headers = {"Content-Type": "application/json", "X-API-Key": API_KEY}
    body = json.dumps(payload)
    try:
        r = requests.post(SERVER_URL, data=body, headers=headers, timeout=HTTP_TIMEOUT)
    except TypeError:          # urequests lama tidak punya argumen timeout
        r = requests.post(SERVER_URL, data=body, headers=headers)
    try:
        if r.status_code != 200:
            raise Exception("HTTP %d" % r.status_code)
        return r.json()
    finally:
        r.close()
```
Data yang gagal dikirim otomatis masuk ke Offline Buffer (maks 10).

### B. Log Debug di Serial Monitor
Tiap putaran mencetak tahap yang sedang berjalan, sehingga lokasi macet langsung kelihatan:

```text
Baca inverter: True None          <- Modbus OK
Kirim ke http://10.10.66.121:8080/api/ingest
Server OK, perintah: 0            <- server menjawab 200
```

| Log | Artinya |
| :--- | :--- |
| `Baca inverter: False timeout` | Masalah di Modbus (kabel A/B, wiring MAX485, slave ID) |
| `Gagal kirim ke server: HTTP 401` | `API_KEY` tidak cocok |
| `Gagal kirim ke server: [Errno 113] EHOSTUNREACH` / `ETIMEDOUT` | IP/port salah, beda jaringan, atau firewall |

### C. Watchdog
`wdt.feed()` ditambah di `detect_slave()`, setelah baca inverter, setelah tulis register, tiap percobaan read-back, dan tiap kirim offline buffer. Ini mencegah restart tak perlu (WDT 60 detik) saat banyak operasi lambat berurutan.

## 4. Perubahan Dashboard (`dashboard.html`)

### A. Setingan "SAAT INI"
Sebelumnya dropdown tidak menunjukkan mana nilai yang benar-benar aktif di inverter. Sekarang tiap setingan menampilkan:

```text
┌──────────────────────────────────────────────────────┐
│ Prioritas Output                      [ Panel   ▼ ]  │
│ SAAT INI: [ Baterai ]                 [ SET ]        │
│ ● BELUM DITERAPKAN                                   │
└──────────────────────────────────────────────────────┘
```

- **SAAT INI**: nilai aktif di inverter (dari holding register). Contoh: `Baterai`, `56.0 V`, `60 A`.
- Dropdown / kolom angka: nilai yang akan dikirim.

### B. Status Perubahan
| Status | Kapan muncul |
| :--- | :--- |
| `● BELUM DITERAPKAN` | Nilai di kontrol berbeda dari SAAT INI. Kartu diberi garis tebal |
| `⏳ MENUNGGU INVERTER...` | Perintah sudah dikirim, belum terbaca berubah di inverter |
| `✕ GAGAL` / `✕ TIMEOUT` | Inverter menolak atau tidak menjawab, lengkap dengan keterangan |
| *(kosong)* | Nilai kontrol sama dengan SAAT INI |

### C. Alur Perubahan Setingan

```text
[User] ubah dropdown ──> tampil "BELUM DITERAPKAN"
   │
   ▼ klik SET
[Popup] Dari: Baterai  ->  Ke: Panel  ── Lanjutkan?
   │
   ▼ OK
[Server] antre perintah ──> tampil "MENUNGGU INVERTER..."
   │
   ▼ siklus ESP32 berikutnya (≤ 3 dtk)
[ESP32] tulis register ──> jeda 1 dtk ──> read-back ──> lapor hasil
   │
   ▼ ESP32 baca ulang holding register (otomatis setelah perintah)
[Dashboard] SAAT INI berubah jadi "Panel", status hilang   ✔
   │
   └─ jika gagal: tampil "✕ GAGAL: <alasan>"
```

### D. Perbaikan Lain
- Dropdown tidak lagi kembali ke nilai lama sesaat setelah klik SET.
- Setingan tetap tampil walau data live inverter belum ada.
- Ganti device di dropdown mereset panel setingan dan status pending.
- Error dari server (misal "Masih ada antrean", "Device offline") tampil sebagai popup.
- Label: **Voltase** (bukan Tegangan), **Voltase / Ampere**.
- Grafik memakai **Apache ECharts** (CDN jsDelivr).

### E. Kapan Nilai SAAT INI Diperbarui
ESP32 membaca holding register tiap `HOLDING_EVERY = 5` putaran (≈ 15 detik) dan langsung setelah menjalankan perintah. Jadi setelah klik SET, nilai SAAT INI bisa telat hingga ±15 detik. Itu normal.

### `.env`
```env
DASHBOARD_USER=admin
DASHBOARD_PASS=PasswordRahasiaAnda
API_KEY=KunciRahasiaESP32Anda

# Kosongkan jika belum dipakai (token palsu memicu "Telegram error: 404")
TELEGRAM_TOKEN=
TELEGRAM_CHAT_ID=

AUTO_SOC_ENABLED=True
SOC_LOW_THRESHOLD=30
SOC_HIGH_THRESHOLD=85

OFFLINE_AFTER_S=15
CMD_TIMEOUT_S=40
SERVER_PORT=8000
```

### `docker-compose.yml`
```yaml
services:
  spf-gateway:
    build: .
    container_name: growatt-server
    ports:
      - "${SERVER_PORT:-8000}:8000"
    volumes:
      - ./data:/app/data
    env_file:
      - .env
    restart: unless-stopped
```

### Perintah Penting
> Docker versi baru memakai `docker compose` (tanpa tanda hubung). `docker-compose` bisa memberi `command not found`.

| Tujuan | Perintah |
| :--- | :--- |
| Jalankan / update kode | `docker compose up -d --build` |
| Ubah `.env` | `docker compose up -d --force-recreate` (**`restart` tidak membaca ulang `.env`**) |
| Lihat log | `docker compose logs -f` |
| Cek env di dalam container | `docker compose exec spf-gateway printenv API_KEY` |
| Matikan | `docker compose down` |

```python
WIFI_SSID = "NAMA_WIFI"
WIFI_PASS = "PASSWORD_WIFI"
SERVER_URL = "http://IP_SERVER:PORT/api/ingest"   # PORT = SERVER_PORT di .env
API_KEY = "KunciRahasiaESP32Anda"                 # sama persis dengan .env
DEVICE_ID = "esp32_rumah"                         # unik per ESP32
```

**Wiring MAX485 → ESP32:** `VCC`→5V, `GND`→GND, `DI`→P17 (TX2), `RO`→P16 (RX2) **(wajib pembagi voltase 1k & 2k)**, `DE+RE`→P4, `A/B`→port RS485 inverter (tukar jika gagal).

## 7. Cara Tes Cepat

**1. Server hidup:**
```bash
curl http://IP_SERVER:PORT/health
```
Hasil: `{"status":"ok","devices":[...]}`

**2. Kirim data palsu (tanpa ESP32):**
```bash
curl -X POST http://IP_SERVER:PORT/api/ingest \
  -H "X-API-Key: KUNCI" -H "Content-Type: application/json" \
  -d '{"device":"test","ok":true,"live":{"pv1_w":500,"pv2_w":300,"out_w":400,"bat_v":52.1,"soc":50,"bat_w":-200,"grid_v":220,"inv_temp":35,"fault":0}}'
```
Hasil: `{"commands":[]}` dan device `test` muncul di dropdown.

**3. Alur diagnosis:**

```text
Dropdown kosong?
  ├─ Log Docker tidak ada "POST /api/ingest" ──> jaringan / IP / port / firewall
  ├─ Ada "POST /api/ingest ... 401"            ──> API_KEY beda
  └─ Ada "200 OK" tapi "Baca inverter: False"  ──> Modbus (kabel A/B, MAX485)
```

## 8. Troubleshooting

| Gejala | Penyebab | Solusi |
| :--- | :--- | :--- |
| Log server penuh `POST /api/ingest 401` | `API_KEY` ESP32 ≠ `.env` | Samakan. Cek spasi tersembunyi: `cat -A .env \| grep API_KEY` harus `API_KEY=xxx$` |
| Server hang, ESP32 timeout | Deadlock (`Lock` biasa) | Pastikan `lock = threading.RLock()` lalu rebuild |
| `Telegram error: HTTP Error 404` | Token Telegram palsu/salah | Kosongkan `TELEGRAM_TOKEN` dan `TELEGRAM_CHAT_ID`, atau isi token asli dari @BotFather |
| ESP32 tidak sampai ke server | `SERVER_URL` salah / port beda dengan `SERVER_PORT` | Samakan IP dan port |
| Ubah `.env` tapi tidak berubah | `restart` tidak membaca ulang `.env` | `docker compose up -d --force-recreate` |
| Ubah `server.py` tapi tidak berubah | Kode ada di image | `docker compose up -d --build` |
| `docker-compose: command not found` | Docker versi baru | Pakai `docker compose` |
| Warning `attribute version is obsolete` | Baris `version:` usang | Hapus baris `version:` di `docker-compose.yml` |
| Dashboard minta login terus setelah restart | Sesi disimpan di RAM | Login ulang |
| SAAT INI tidak berubah setelah SET | Menunggu pembacaan holding (≤ 15 dtk) atau perintah gagal | Tunggu, lihat status di kartu dan Log Perubahan |
| Setingan `GAGAL` | Inverter menolak (mode Fault, nilai tidak valid, EEPROM sibuk) | Cek keterangan di kartu, coba lagi |
| Grafik tidak muncul | Browser tidak bisa memuat ECharts dari CDN | Hubungkan ke internet, atau unduh `echarts.min.js` dan simpan lokal |
| `Inverter tidak menjawab` | Kabel A/B terbalik atau salah port RS485 | Tukar A dan B |

## 9. Catatan Keamanan & Batasan

- Komunikasi masih **HTTP polos**. Pakai hanya di LAN, atau pasang reverse proxy HTTPS jika diakses dari luar.
- `/health` terbuka tanpa login dan menampilkan daftar `device_id`.
- Ganti `DASHBOARD_PASS` dan `API_KEY` default sebelum dipakai harian.
- Perintah Auto-SOC hanya dikirim jika nilai register berbeda dari target, agar EEPROM inverter tidak ditulis berulang.
- Antrean perintah (`commands`) disimpan di RAM, hilang saat container restart. Riwayat tetap ada di tabel `audit`.
- Tabel `readings` belum punya pembersihan otomatis. Rencana: hapus data lebih dari 30 hari.
